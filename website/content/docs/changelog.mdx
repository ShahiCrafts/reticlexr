All notable changes to this project are documented here. The project
follows [Semantic Versioning](https://semver.org/).

## 1.1.0 — Unreleased

The audit-remediation release. Summary: the full entry is in the
repository `CHANGELOG.md`.

### Package rename

- The package was renamed from `capacitor-arcore` to **reticlexr**
  before its first publish. `capacitor-arcore` was never published
  to npm; there is nothing to migrate from the registry.

### Behavior changes

- Tap places the first model; dragging moves it. Once a model is
  active, taps do nothing. Drag-to-place still works.
- Meshopt and KTX2 model support: the Meshopt decoder is wired
  into the model loader, and a new `ktx2TranscoderPath` session
  option enables KTX2 textures. The demo models were re-encoded
  with both: 12.36 MB to 5.53 MB total download, texture memory
  51.7 MB to 7.0 MB, geometry and animation unchanged.

- **Native Android is scoped to session + hit-testing (Option B).**
  `placeModel`, `moveModel`, `setTransform`, `setMaterial`,
  `removeModel`, `getPlacedModels` and `clearModels` reject with
  `NOT_IMPLEMENTED` on native; models render via WebXR. Native
  lifecycle (pause/resume/destroy) is wired, `checkSupport` returns
  real ARCore availability, and hit tests create real anchors.
- **The library manifest no longer forces AR-required:**
  `android.hardware.camera.ar` and `android.hardware.camera` are
  `required="false"`; AR-required is a documented opt-in.
- **Screenshots are opt-in:** `enableScreenshots: true` at session
  start; `lightEstimation` no longer implies `camera-access`.
- **One model identifier** (`modelId`) and **one coded-error
  convention** (`ARError`) across all layers.
- The native event bridge installs lazily; the package declares
  ESM + an exports map; `three` and `@capacitor/core` are peer
  dependencies.

### Added

- Drag-to-move: with a model placed, one finger drags it across
  surfaces; the engine re-aims a hit test at the finger every
  frame, so the model stays under it.
- ARView debug readout: `enableCustomization` accepts `debug`
  and `onDebug`. Entries report each tap's pixel and normalised
  point, the hit coordinate, the model's measured base centre,
  and where its centre lies after the tap, so placement accuracy
  can be verified on a phone. The live demo shows them in an
  on-screen panel during AR.
- `framebufferScale` session option: scales the XR render target
  (0.85 ≈ 28% fewer fragments). The live demo runs at 0.85.

- `reticlexr/react` subpath for `useARCore`, plus a per-instance
  `useARCore({ engine })` option.
- `getPlacedModels()` / `clearModels()` on the engine, `ARView`,
  the facade and the hook.
- Hand-written TypeScript declarations; a Vitest suite; committed
  lockfiles; a CI workflow (type-check, tests, example build,
  Gradle assemble).

### Fixed
- Tap and drag accuracy: tap-to-place, tap-to-move and drag
  coordinates are now normalised against the overlay element's
  own bounding rect instead of the window size, so any
  difference between the two (insets, embedding, a resized
  overlay root) no longer displaces the model from the touched
  point. A new end-to-end harness verifies the whole chain
  against an analytic floor: taps land within 0.0001 m of the
  predicted point and project back to the tapped pixel within
  half a pixel.
- Overlapping plane dots: when the same surface is reported as
  overlapping planes, their dot fields no longer overlap. All
  planes' dots are rebuilt in one pass over a shared occupancy
  grid (largest plane first), so each surface shows a single
  clean dot grid.
- Placement centre hardening: the base centre is measured from
  the model's main mesh cluster, so detached stray geometry in
  a GLB (a leftover mesh sitting away from the body) can no
  longer drag the measured centre, and with it the tap point,
  off the model. The footprint used for shadows and base rings
  is measured the same way.

- The audit's BUG / LEAK / PERF / NAT / COMPAT findings: transform
  normalisation (no more `NaN` placements), hook plane counts,
  ray-based hit testing, disposal under an ownership rule with an
  LRU model cache, `InstancedMesh` plane dots, the reference-space
  fallback chain, a bounded native availability retry, and more.
- Tap-to-move (device report, 2026-11-17): a placed model could
  never be relocated, because the gesture layer only placed.
  `ARView.moveModel({ x, y })` is new, and the tap gesture now moves
  the active model to the tapped surface point.
- The live demo no longer carries one model's texture onto the
  next: it switches models with `{ preserveMaterial: false }`, so
  each model keeps its own authored look.
- Rendering economy: the plane dot grid is capped at 2,048 dots
  per plane, animation mixers skip hidden models, and skinned
  meshes opt out of frustum culling in placement clones.

- Drag tracking rebuilt (device report, 2026-11-17): the first
  drag ran one promise-based hit test per pointer move, serialised
  behind a queue, so the model trailed the finger and landed where
  it had been. The engine now tracks the drag inside its render
  loop (`beginDragMove` / `updateDragPoint` / `endDragMove`), and
  one final move lands the model exactly on the release point.
- Placement is by base centre: models whose files carry their
  geometry offset from the origin (the demo astronaut sits about
  0.92 m from its origin and 0.28 m below it) now land on the
  tapped point and stand on the surface, instead of appearing
  displaced and sunk.

### Deprecated

- `anchorId` → `modelId`; engine `modelPath` → `modelUrl`; ARView
  result `reason` → `code`; `useARCore` from the package root →
  `reticlexr/react`. All keep working throughout 1.x.

## 1.0.0 — 2026-09-25

### Added

- High-level `createARView()` abstraction.
- WebXR and Android ARCore integration layers.
- Surface detection, dotted plane feedback, and placement reticle.
- Tap-to-place, pinch-to-scale, and two-finger rotation gestures.
- GLB/GLTF loading, model preloading, and in-place model switching.
- Runtime material, color, and texture customization.
- AR screenshot API and React DOM overlay support.
- React/Vite example application with LAN HTTPS development tooling.

<Note title="Correction: read the parity claim carefully">
The original 1.0.0 entry lists "WebXR and Android ARCore integration
layers" side by side, which readers reasonably took as feature parity.
The v1.0.0 audit verified that the Android layer provides session
management, hit testing and surface events, but **does not render
models**, model rendering, styling and screenshots are WebXR-runtime
features. This note is the correction; the entry above is otherwise
reproduced as published. See
[WebXR vs native ARCore](/docs/concepts/webxr-vs-native) for the
verified split.
</Note>
