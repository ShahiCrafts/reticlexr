## The built-in wiring: `enableCustomization`

The fastest way to get gestures is `ARView.enableCustomization()`. It
attaches a gesture controller to the view's overlay and wires the gestures
to the active model:

```js title="gestures.js"
const cleanup = ar.enableCustomization({
  // REQUIRED: which model a tap should place. A plain URL string works;
  // pass a function and it is called on every tap, so the model placed
  // can follow the user's current selection.
  modelUrl: () => currentModelUrl,
  onTap: () => console.log('placed'),
  onScale: (factor) => console.log('scale is now', factor),
  onRotate: (radians) => console.log('rotationY is now', radians),
});

// Later, to detach:
cleanup();
```

| Gesture | Effect |
| --- | --- |
| One-finger tap | Places the current `modelUrl` at the tap point (only when no model is placed yet) |
| Pinch (two fingers, in/out) | Scales the active model — `ARView.setScale` clamps to **[0.1, 5]** |
| Twist (two fingers, rotate) | Rotates the active model around Y |
| Drag (one finger) | Available in the standalone controller (`onDrag`); `enableCustomization` does not bind it to the model |

<Note>
`modelUrl` accepts a plain URL string or a `() => string` function.
The function form is called on every tap — use it when the model to
place can change between taps (the example app reads the latest
selected product from a ref). A plain string always places the same
model. (Before 1.1.0 only the function form worked; a string threw a
`TypeError` inside the tap handler.)
</Note>

Overlay elements marked with `data-ui` are ignored by the gesture layer,
so your buttons and sheets never double as scene gestures.

## The standalone controller

For custom interactions, use the exported controller directly. It is
framework-agnostic Pointer Events code and knows nothing about AR:

```js title="custom-gestures.js"
import { createARGestureController } from 'reticlexr';

const gestures = createARGestureController({
  element: document.querySelector('#ar-overlay'), // required
  onTap: ({ x, y }) => { /* pointerup point, px */ },
  onDrag: ({ dx, dy, x, y }) => { /* per-move deltas, px */ },
  onPinch: ({ factor, center }) => { /* factor is incremental */ },
  onRotate: ({ delta, center }) => { /* delta in radians, incremental */ },
  tapMaxDuration: 260,   // ms — longer presses are not taps
  tapMaxDistance: 12,    // px — further movement is not a tap
  preventDefault: true,
  ignoreSelector: '[data-ui]',
});

// When the view goes away:
gestures.destroy();
```

Payload semantics worth knowing:

- `onPinch`'s `factor` is **incremental** — relative to the previous move
  event, not the gesture start. Multiply your running scale by it.
- `onRotate`'s `delta` is likewise incremental, in radians, wrapped to
  ±π.
- A tap is a pointer down/up pair within `tapMaxDuration` and
  `tapMaxDistance`. One known quirk: a `pointercancel` (system
  gesture, notification) that happens to be short and stationary is
  currently treated as a completed tap and can place a model.

## Driving transforms yourself

If you bypass `enableCustomization`, the facade exposes the same
operations the gestures use:

```js
ar.setScale(1.4);        // clamped to [0.1, 5], applied uniformly
ar.rotateBy(Math.PI / 8); // accumulates rotationY, radians
```

One scale range everywhere since 1.1.0: [0.1, 5], enforced by the
engine itself (the facade and the native registry use the same
limits). In v1.0.0 the layers disagreed — facade [0.1, 5], engine
unclamped, native [0.25, 3].
