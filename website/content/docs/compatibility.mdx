The tables below separate **code-level requirements** (verified by
reading the source) from **tested support** (real device runs,
recorded in [Devices](#devices)). Do not read a requirement as a
support promise: a feature is only "tested" once it has been run on
a recorded device.

## WebXR runtime (browser)

| Requirement | Source | Tested |
| --- | --- | --- |
| Secure context (HTTPS or `localhost`) | WebXR platform rule; `checkSupport()` reports it with a distinct `INSECURE_CONTEXT` code | — |
| `immersive-ar` session support | `navigator.xr.requestSession('immersive-ar', …)` | Chrome 157 · Android 12 ✓ |
| `hit-test` feature | Required feature at session creation | Chrome 157 · Android 12 ✓ |
| `local-floor` feature | Requested first at session creation; falls back to `local`, then `viewer` when unavailable | — |
| `plane-detection` | Optional feature; dots/meshes appear when granted | Chrome 157 · Android 12 ✓ |
| `light-estimation` | Optional; requested when light estimation is on | — |
| `camera-access` | Optional; requested **only** when the session starts with `enableScreenshots: true` (for screenshots, not implied by light estimation) | See the device notes |
| `dom-overlay` | Optional; requested when an overlay element is provided | Chrome 157 · Android 12 ✓ |

The documented test path is **Chrome on an ARCore-capable Android phone**
(see [Phone testing](/docs/getting-started#https-and-phone-testing)).
Chrome versions tested so far: **157.0.8103.78** on Android 12. No
minimum Chrome version is established: only versions actually run
are listed.

iOS Safari does not expose the immersive-ar WebXR flow. The browser
runtime is not an iOS path.

## Native Android runtime (Capacitor)

| Item | Value | Notes |
| --- | --- | --- |
| Minimum Android SDK | 24 | `minSdk` default in `android/build.gradle` (overridable by the host project) |
| Compile / target SDK | 36 / 36 | Defaults, overridable |
| ARCore library | `com.google.ar:core` 1.40.0 | Device must be ARCore-capable with Google Play Services for AR |
| Filament | 1.52.0 | Camera-background rendering |
| Java | 21 | Source/target compatibility |

The native Capacitor runtime has not been device-tested yet. The
WebXR runtime has, see [Devices](#devices).

<Note>
The library's Android manifest declares the AR feature (and the
plain camera feature) as `required="false"`, which merges into
your app: host apps stay installable on non-AR devices. Making
AR required is an opt-in from your own manifest, see the
[installation guide](https://github.com/ShahiCrafts/reticlexr/blob/main/docs/INSTALLATION.md).
</Note>

## Frameworks and tooling

| Item | Requirement | Notes |
| --- | --- | --- |
| React | `>=16.8.0` (peer) | Only the hook needs it (import it from `reticlexr/react`). The root entry still re-exports it as a deprecated alias, so root imports still pull React in 1.x |
| `@capacitor/core` | `^8.5.2` (peer) | Provided by the host Capacitor app |
| `three` | `^0.180.0` (peer) | Provided by the host app, one shared copy; duplicates break GLTF class identity |
| Module format | ESM (`type: module`) with an `exports` map | Subpaths: `.`, `./react`, `./web`, `./ar-view`, `./gestures`, `./package.json` |
| TypeScript | Hand-written declarations ship (`src/*.d.ts`) | JSDoc in the implementation is type-checked by `npm run check-types` (`tsc --checkJs`) |

## Devices

| Device | OS | Browser | Date | Result |
| --- | --- | --- | --- | --- |
| Redmi Note 9S | Android 12 | Chrome 157.0.8103.78 | 2026-11-17 | WebXR demo run, see notes below |
| Samsung Galaxy A24 (SM-A245F) | Android 16 | Chrome 157.0.8103.50 | 2026-11-17 | WebXR demo run, tap-to-place confirmed |

Follow-up the same day: when the demo moved to tap-only placement,
tap-to-place failed on the Redmi: the per-tap hit test gave up on
its first (still empty) results frame, so taps missed silently.
Fixed in the library (the point hit test now tolerates a short
grace of empty frames and falls back to the reticle hit, and a
missed tap now surfaces an on-screen hint), and confirmed working
on both devices above.

Notes from the Redmi Note 9S run (the library's first recorded device
test, against the live demo):

- Session start, surface detection, tap-to-place and in-place model
  switching all worked; switching was smooth.
- Pinch-to-scale and twist-to-rotate worked but were jittery and
  hard to control. Root causes found in the gesture pipeline the
  same day, no `touch-action: none` on the overlay, unsmoothed
  digitizer samples, and transform state committed only after an
  async engine call, and fixed in the library source. A confirming
  re-test is pending.
- Screenshots failed with `CAMERA_CAPTURE_UNAVAILABLE`: the demo
  did not start its session with `enableScreenshots: true`, so
  camera access was never requested (WebXR can only grant it at
  session start). The demo now opts in; a confirming re-test is
  pending.

If you run the demo on your phone, reporting the device model,
Android version and Chrome version (in a GitHub issue) directly
extends this table.
